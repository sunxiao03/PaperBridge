# PaperBridge V1 产品规格

状态：已接受，作为开发基线  
日期：2026-08-10

## 1. 产品定位

PaperBridge 是仅面向 Windows 的本地英文科研论文阅读器，核心任务是稳定阅读英文 PDF，并借助 OpenAI 或 DeepSeek 提供术语一致的中文翻译和有原文依据的阅读辅助。

产品首先供项目所有者个人使用，同时以易安装、无内置密钥、数据留在本机的形式发布到 GitHub，供朋友试用。它不是 Zotero 替代品，也不建设云端服务。

发生取舍时依次保障：

1. PDF 阅读稳定性；
2. 英译中质量；
3. 核反应堆物理术语准确性与一致性；
4. 阅读响应速度；
5. 内存可控；
6. 缓存与 API 成本；
7. AI 阅读辅助；
8. 文献管理；
9. 装饰性 UI。

## 2. V1 边界

### 2.1 支持

- Windows 10/11 x64；
- 具有正常可选择文本层的英文 PDF；
- 本地单个或批量导入；
- 本地文献管理、阅读、翻译、术语、批注和当前论文问答；
- OpenAI、DeepSeek 及其兼容 Base URL；
- 用户主动触发的联网元数据补全；
- 用户明确选择时，将整份 PDF 交给支持该能力的 API。

### 2.2 不支持

- macOS、Linux、Web 和移动端；
- OCR 和扫描件识别；
- Zotero、云同步、账户、多用户和团队协作；
- 后端服务器、遥测、自动更新；
- 跨论文向量库、联合问答和关系图谱；
- 双语 PDF 导出、引用格式管理和投稿管理。

参考项目只用于研究交互，不继承其代码或架构。

## 3. 不可破坏的工程约束

- 不修改用户导入的原 PDF；
- PDF 渲染、文本提取、译文、批注和索引各自分层；
- 页面按需渲染，缓存受全局预算约束；
- 关闭标签后取消相关任务并释放文档、页面和位图等原生资源；
- 所有后台任务可取消，有界并发，不创建无上限任务；
- API 请求按文档、文本、模型、提示词和术语版本去重；
- 用户编辑内容与机器译文分层保存，重新翻译不得静默覆盖用户编辑；
- 真实 API Key 只进入 Windows Credential Manager，任何日志均不得输出 Authorization Header；
- 诊断日志默认本地保存，不采集文献内容和用户行为。

## 4. 文献库

必须支持导入、批量导入、从库中移除、逻辑文件夹/分类、标签、收藏、最近阅读、阅读进度、阅读位置恢复和搜索。

可搜索元数据包括标题、作者、年份、期刊和 DOI。元数据首先读取 PDF 自带信息，并从首页可提取文本中进行有限识别。只有用户点击“联网补全文献元数据”后，才访问 Crossref 等公开元数据服务。

默认采用受管理文献库：导入时复制 PDF 到应用数据目录，以内容哈希去重。删除分为两个动作：

- 从文献库移除，但保留受管理文件；
- 永久删除受管理文件，必须明确确认。

文件夹移动是文献库中的逻辑移动，不擅自移动用户原始文件。

## 5. PDF 阅读

必须支持缩放、PDF 内搜索、目录、页面缩略图、多标签、位置恢复、高亮、下划线、文本批注和书签。

批注存储文档版本哈希、页码、文本指纹、字符范围和页面四边形坐标。批注可以关联英文原文、当时显示的中文译文及用户备注。全局设置可关闭“批注关联译文”。若 PDF 内容被替换，视为新的文档版本，不保证旧坐标自动迁移。

公式保持原样，不翻译。翻译用文本抽取应识别正文、标题、章节标题、图表题、可提取的表格文字、脚注和参考文献文字；无法可靠排序的内容必须保留来源页码并降低版面分析置信度。

## 6. 翻译

交互翻译以 PDF 原页选区为唯一入口：用户在原文上选择多少就翻译多少，单击英文单词时扩展到完整单词。不得要求用户先把整页文本载入独立原文框，也不提供“单词、选区、句子、段落、当前页”等重复粒度按钮。派生双语视图仍可显式翻译当前页或全文，并支持学术解释。

### 6.1 显示模式

- PDF 原页：在高清页面渲染上叠加可选择文字层，选区直接映射 PDF 字符和坐标；
- 右侧栏：显示紧凑的当前选区预览和主要译文编辑区，不重复展示整页原文；
- 段落双语：在独立的派生阅读视图中按“英文段落—中文译文”展示，不向 PDF 页面插入内容；
- 左右对照：左侧原 PDF，右侧结构化中文内容，按段落或页码同步。
- AI 助读：使用独立非模态窗口，可与主窗口翻译栏同时显示。

段落双语和精细同步仅在版面分析置信度达到阈值时启用。双栏顺序、公式、浮动图表或跨页段落无法可靠判断时，自动退化为右侧栏或按页左右对照，并明确显示退化状态。

### 6.2 启动、缓存和失败

打开文献后优先处理当前页，再以有界队列预翻译少量后续页；用户移动阅读位置时调整队列。全文翻译是独立的显式操作。

缓存键至少包括文档版本、原文哈希、段落身份、语言方向、服务商、模型、默认提示词版本、用户指令版本和术语约束版本。

机器译文、用户编辑稿和当前展示稿分别保存。重新翻译默认生成新机器版本；存在用户编辑时，由用户选择保留编辑、查看差异或用新译文替换。

仅对超时、限流和可恢复的服务端错误自动重试，最多 3 次，采用指数退避和随机抖动。鉴权错误和无效请求不盲目重试。最终失败显示原因、重试及更换 API 后重试操作。

### 6.3 上下文

翻译按 Token 预算选取标题、摘要、章节、相邻段落、已确认术语和相关专业词条。只发送本次任务相关术语的首选译名及必要别名，不发送完整解释正文。

## 7. 术语系统

优先级固定为：用户个人术语 > 已启用的内置专业术语库 > 模型判断。

词条至少包含英文术语、首选中文译名、中英文别名、类别、简短专业解释、备注、来源参考、优先级、审核状态和词库标识。

个人术语支持新增、修改、删除、搜索、分类、备注、解释、覆盖内置词条、导入和导出。数据结构允许以后安装多个专业词库，不能写死为单一核物理词库。

V1 目标提供 500–1000 个高频核反应堆物理术语，但数量不作为单独完成依据。每条术语应记录来源和审核状态。软件可以协助整理和交叉检查，权威性由人工审核确认。不得复制标准或教材中的长篇受版权保护定义。

用户修改译文后，软件可以识别潜在术语变更并询问是否加入个人术语库；未经确认不得自动学习或批量改变词库。

## 8. AI 阅读辅助

支持选中文字翻译、解释或翻译并解释；支持当前章节结构化总结和整篇论文分块—综合总结。总结结果按文档和提示词版本缓存。

当前论文问答只检索当前文档，允许连续追问。回答中的证据必须来自已提取文本，并包含 PDF 页码、英文原文和章节信息；点击证据跳转相应页。系统无法找到足够证据时必须说明，不伪造页码或引用。

V1 优先使用当前论文的 FTS/BM25、章节结构和有限模型重排，不建立全库向量索引。

## 9. API、隐私和安全

设置包括服务商、API Key、Base URL、模型名称和“高级—自定义 AI 指令”。普通界面不暴露大量采样参数，程序提供可版本化默认值。

发送任何内容前，界面应让用户知道所选服务商会收到必要文本。整份 PDF 上传必须由用户对单次操作明确触发。

真实密钥不得进入源代码、Git 历史、README、示例配置、Issue、日志、崩溃报告、数据库导出、Debug 输出、构建脚本或构建产物。发布前使用自动化工具扫描当前工作树、Git 历史和发布产物。若密钥曾进入历史，必须先吊销，再清理历史。

## 10. 数据、卸载和发布

数据库、翻译缓存、批注、词库、阅读历史、设置和受管理 PDF 均位于明确的本地应用数据目录。数据库采用版本迁移并定期创建可恢复备份。

卸载时让用户选择保留或删除个人数据；删除选项同时包含 Credential Manager 中由本程序创建的凭据。V1 不自动检查更新，由维护者在 GitHub 发布新版本。

## 11. 可测验收门槛

### 11.1 基准语料

维护不含敏感信息且许可允许测试的本地语料清单，至少覆盖：

- 1–20 页短文、100–200 页论文集和至少一份约 500 页长文档；
- 单栏、双栏、公式密集、图表密集、脚注、参考文献和旋转页面；
- 正常文本层、文本顺序异常和字体映射异常样本。

受版权限制的 PDF 不提交到 GitHub，只提交哈希、特征描述和获取说明。

### 11.2 性能门禁

- 冷启动、首屏显示、快速滚动和标签切换均建立可重复基准；
- 渲染缓存有明确字节预算，超限按最近最少使用策略回收；
- 连续执行至少 10 轮“打开多篇—切换—关闭”后，强制回收并等待空闲，私有提交内存曲线应趋于稳定；
- 若后 5 轮内存对轮次呈持续线性增长，视为失败，不以“机器内存足够”豁免；
- 进行 8 小时阅读/滚动耐久测试，无崩溃、句柄持续增长或不可取消任务；
- 全文翻译并发数和待处理队列长度均有配置上限，关闭文档后不再产生新请求。

绝对内存预算在阶段 0 的 PDFium 原型基准完成后冻结，避免在没有测量依据时制定虚假数字。

### 11.3 功能和安全门禁

- 缓存命中时重新打开论文不产生重复 API 请求；
- 相同翻译任务并发触发只发送一次；
- 模拟超时、429、5xx、401、取消和离线状态；
- 用户编辑译文在重新翻译和数据库迁移后不丢失；
- 问答的每条引用能反向定位到页码和英文片段；
- Credential Manager、日志脱敏、工作树/历史/构建产物 Secret 扫描全部通过。

## 12. V1 完成定义

原始需求中的文献管理、稳定阅读、七种翻译方式、四种显示模式、缓存与编辑、术语优先级、批注书签、总结、当前论文有据问答、内存控制、Credential Manager 和发布安全全部通过测试，才标记 V1。

某种复杂版面无法进行段落双语不是程序失败，但必须正确检测并按本规格退化；错误对齐且不提示属于失败。
