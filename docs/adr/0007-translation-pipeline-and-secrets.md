# ADR 0007：基础翻译管线、缓存与密钥边界

- 状态：接受
- 日期：2026-08-10

## 背景

阶段 2 需要支持 OpenAI、DeepSeek 和兼容服务，并在多个入口共享缓存、请求去重、取消、并发限制和错误策略。API Key 不得进入普通设置、数据库、日志或构建产物。

## 决策

- OpenAI、DeepSeek 与兼容服务共用 Chat Completions 协议适配器；Base URL 和模型由非敏感设置决定。
- API Key 按服务商分别存入 Windows Credential Manager，普通 JSON 设置模型没有密钥属性。
- SQLite 数据库升级到版本 3，增加 `translation_cache`。只保存原文 SHA-256、版本化键字段、机器译文、模型、Token 计数和时间；不保存原文正文或 API Key。
- 缓存键覆盖文档内容哈希、原文哈希、翻译粒度、语言方向、服务商、模型、默认 Prompt 版本、自定义指令版本和术语版本。
- 相同缓存键的并发请求共享一个在途操作；所有等待者取消后，底层 HTTP 请求随之取消。
- 每个协调器使用 1–8 的有界并发信号量。超时覆盖排队、重试和请求全过程。
- 429、5xx 和网络连接异常最多重试 3 次，使用指数退避与随机抖动；401、403 和其他 4xx 立即返回。
- 请求 Prompt 明确要求保留公式、变量、单位、引用和标识符，响应只接受译文正文。
- HTTP 错误不读取或拼接响应正文，异常不包含 Authorization Header。

## 影响

缓存和去重行为与具体服务商解耦，切换标签能够取消无消费者的请求。服务商兼容性依赖其实现 Chat Completions 请求和响应结构；真实 API 验证保留为用户通过界面主动执行的可选测试。
