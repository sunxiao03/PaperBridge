# ADR-0001：Windows 技术基线

- 状态：接受
- 日期：2026-08-10

## 决策

应用采用 C#、.NET 10 LTS、WPF、PDFium 和 SQLite + FTS5。V1 只发布 Windows x64 自包含版本，采用 MIT 许可证。

PDF 阅读控件由项目维护虚拟化和缓存策略，不把 WebView2 内置 PDF 查看器作为核心。PDF 批注与译文保存在本地数据库，不写回原 PDF。

## 理由

- WPF 的 Windows 桌面生命周期成熟，便于精确管理原生资源和大型虚拟化列表；
- .NET 10 是当前长期支持版本，自包含发布不要求用户安装运行时；
- PDFium 提供渲染、文本和坐标底层能力，许可证适合 MIT 项目；
- SQLite 适合单用户本地数据，FTS5 足以支撑文献搜索和当前论文检索；
- 避免 Electron 的额外浏览器进程基线，也避免 MuPDF AGPL 对项目许可证的传染性约束。

## 代价

- 项目仅支持 Windows；
- WPF 的现代视觉样式需要自行维护；
- PDFium 原生二进制的版本、架构、校验和及打包需要专门维护；
- PDF 文本阅读顺序并不天然可靠，必须建立置信度与退化机制；
- 自定义阅读控件的开发量高于嵌入现成查看器。

## 重新评估条件

阶段 0 若证明 PDFium 无法在目标语料上稳定提供渲染、字符坐标或资源释放，则在继续产品功能前记录新 ADR，比较其他 PDF 引擎；不得同时长期维护两套核心引擎。
