# ADR 0005：多标签会话与 PDFium 并发边界

- 状态：接受
- 日期：2026-08-10

## 背景

阅读器需要同时打开多篇论文，并为每篇论文保留目录、页模型、阅读位置和可取消的渲染任务。正文与缩略图缓存不能按标签各自分配完整预算，否则内存上限会随标签数量线性增加。

多文档集成测试还确认，当前 PDFiumCore 与随应用分发的 PDFium 组合不能安全地从多个线程同时进入不同文档实例；未同步的跨文档文本提取会导致原生访问冲突。

## 决策

- 每个打开的文献对应一个独立 `ReaderTabSession`，持有 PDFium 文档、页面、缩略图、目录、阅读位置和取消生命周期。
- 正文与缩略图分别共用 256 MiB 和 32 MiB 的进程级 LRU 缓存；缓存键包含标签 ID。
- 标签失活时取消在途渲染并释放 WPF 图像，缓存中的像素数据继续受全局预算控制。
- 标签关闭时保存阅读位置、取消生命周期、删除该标签的缓存条目并显式释放 PDFium 文档。
- 同一文献只能存在一个阅读标签；再次打开时激活已有标签。
- 所有 PDFium 原生调用使用同一进程级同步锁，包括初始化、打开、读取、渲染、关闭和销毁全局库。

## 影响

多标签数量不会乘大渲染缓存预算，关闭标签也具有明确的资源回收路径。PDFium 原生稳定性优先于跨文档并行渲染吞吐量；WPF 层仍异步调度且可取消，因此串行原生调用不会阻塞界面线程。
