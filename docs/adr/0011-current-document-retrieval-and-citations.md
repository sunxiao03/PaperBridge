# ADR 0011：当前文档检索与可验证引用

- 状态：Accepted
- 日期：2026-08-11

## 决策

V1 的论文问答仅检索当前打开文档。PDFium 提取的文本经既有版面分析器分成最多 3000 字符的页内单元，PDF 目录决定章节路径。本地检索使用词元精确匹配的 BM25，包含词频、文档频率和分块长度归一化。中文或连续追问可调用模型产生有限英文检索词，但模型不返回页码，不创建证据记录，也不改变本地文本内容。

排名后的候选分块由应用生成当次请求专用的 `E1…En` 标识。模型回答不允许声称页码，每个事实性句子必须引用已分配标识。本地校验器遇到空引用、未知标识、未引用事实句或直接页码时拒绝答案。界面中的 PDF 页码、章节和英文摘录始终来自候选分块，而不是从模型文本解析得到。

章节和全文总结使用有界的分块—综合树。SQLite 版本 7 的 `reading_assistant_cache` 按文档内容哈希、任务类型、输入哈希、服务商、模型、Prompt 版本和用户指令版本隔离。选区解释和总结可缓存；问答及会话不持久化。

## 原因

让模型同时检索、选择页码和生成引文会把不可校验的序列生成当作证据。当前文档规模下，本地 BM25 可以用有限内存提供可重现的候选集，且每条候选天然保留页码和原文。把模型限制在“基于已给证据组织回答”的范围内，可以将页码和英文引文变成应用可审计的数据。

## 后果

- 同义改写、纯中文提问和指代性追问依赖有界英文检索词展开，其召回率低于专用跨语言向量索引；
- 模型给出了人类看似合理但引用格式不安全的回答时，应用会拒绝展示而不是自动修补；
- 证据卡可以稳定反查和跳转，但不声称本地校验能自动证明复杂自然语言推理的语义正确性；
- V1 不保存问答历史，不建立全库向量索引，这些可在用户明确选择隐私和存储策略后扩展。
