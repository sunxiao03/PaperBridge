# PaperBridge 执行计划

本项目采用逐阶段、可运行、设门禁的交付方式。性能、安全和资源释放从第一天开始测试，不集中留到发布前补救。

## 阶段 0：技术验证与工程基线

交付物：

- Git 仓库、解决方案结构、本地发布检查、代码规范和 MIT 许可证；
- WPF 壳、领域层、基础设施层和测试工程；
- PDFium 原生依赖加载、单页渲染、文本及坐标提取原型；
- 虚拟化页面列表和带字节预算的渲染缓存原型；
- 打开/关闭循环的内存、句柄和原生资源基准；
- SQLite 迁移原型；
- Windows Credential Manager 写入、读取、删除及日志脱敏测试；
- 基准 PDF 语料清单模板。

退出门禁：PDFium 方案能够提供渲染、选择所需文本坐标并显式释放资源；若失败，在进入产品功能开发前更换引擎。

## 阶段 1：阅读器基础

实现受管理文献库、批量导入、哈希去重、逻辑分类、搜索、基础元数据、目录、缩略图、多标签、阅读位置恢复和按需页面渲染。

当前进度：阶段 1 的功能范围已经实现，包括受管理文献库、批量导入、SHA-256 去重、基础元数据与首页 DOI 提取、元数据 FTS5 搜索、逻辑分类、标签、收藏及筛选、最近阅读排序、两种文献移除方式、目录、虚拟化缩略图、多标签、阅读位置恢复和按需页面渲染。数据库已迁移到版本 2；逻辑分类不会移动用户原始 PDF。合成 500 页、5 标签、12 轮资源基准已经通过；真实复杂版面语料和 8 小时耐久门禁仍待执行。

退出门禁：长文档和多标签基准通过，关闭标签后没有持续性内存或句柄增长。

## 阶段 2：API 与基础翻译

实现服务商适配、Credential Manager、选择/单词/句子/段落/当前页翻译、版本化缓存、请求去重、取消、有界并发和重试策略。

当前进度：OpenAI、DeepSeek 与兼容 Base URL 适配、Credential Manager 设置、SQLite 版本 3 缓存、并发去重、有界队列、取消、超时、分类重试，以及单词、选区、句子、段落和当前页右侧栏翻译已经实现。自动测试使用伪 HTTP Handler 覆盖缓存、去重、429、5xx、401、离线、超时、取消和敏感信息边界；真实 API 冒烟由用户通过界面可选执行。

退出门禁：伪 HTTP 服务的端到端协议冒烟和异常矩阵通过；密钥、Header 和请求敏感字段不进入日志及数据库。真实 API 冒烟由用户通过界面可选执行，不将提供真实密钥作为自动验收前提。

## 阶段 3：专业术语系统

实现多词库数据模型、个人词库、优先级合并、Prompt 约束、导入导出、来源和审核状态，以及译文修改后的确认学习流程。

内置术语按主题小批量加入，每批进行来源记录、重复冲突检查和人工审核，不把“生成 1000 条”当作完成条件。

当前进度：SQLite 已迁移到版本 4；多词库、个人词库、启用状态、来源、审核状态、别名、类别、解释、备注和优先级均已持久化。冲突顺序固定为个人术语、已启用且审核通过的内置术语、模型判断。翻译前只选择原文及上下文中实际出现的最多 64 条约束，并把确定性术语版本写入缓存键。界面支持词库管理、搜索、逐条审核、CSV/TSV 导入导出，以及从用户编辑后的译文显式确认到个人词库。内置“核反应堆物理”起始批次共 24 条，全部以待审核状态交付，不会在用户确认前影响翻译。

退出门禁：迁移、持久化、冲突解析、边界匹配、版本变化、导入导出和 Prompt 注入均有自动测试；未审核或已禁用词条不会进入请求；用户修改译文不会被静默学习。

## 阶段 4：双语阅读与全文翻译

实现浮窗、右侧栏、派生段落双语视图、左右对照、置信度判断、退化提示、滚动映射、预翻译调度和全文翻译队列。

当前进度：SQLite 已迁移到版本 5，按文档哈希、页码和稳定段落标识保存原文锚点、机器译文、用户编辑稿、模型/提示词/术语版本及版面置信度。阅读器提供 PDF、段落双语、左右对照、右侧栏和翻译浮窗；左右对照按同一段落集合联动滚动并可反向定位页码。版面分析使用逐字符坐标覆盖、多栏分布、公式符号密度、段落碎片和跨页迹象计算置信度，低于阈值时自动切换按页对照并显示原因。进入双语视图时仅按“当前页 + 后两页”预翻译；全文翻译必须显式启动，可取消且保留已完成结果。队列最多 32 个等待页、2 个执行页，单页最多 80 个段落、单段最多 3000 字符，活动视图最多保留 200 段，翻译缓存最多 20000 条，页面位图继续受既有字节预算约束。

机器重译只更新机器层；存在用户编辑稿时继续展示用户稿，只有用户明确选择“恢复机器稿”才删除编辑层。真实 API 的费用与内容发送仍由用户通过服务设置和显式操作控制。

退出门禁：复杂版面不会静默错配；关闭文档能取消后续请求；队列、缓存和内存均受上限约束。

## 阶段 5：高亮、批注和书签

实现基于原文指纹和页面四边形的高亮、下划线、批注、书签，以及是否关联译文的设置。

当前进度：SQLite 已迁移到版本 6，以文档 ID、内容 SHA-256、页码、原文偏移与指纹、前后文和归一化 PDF 坐标保存高亮、下划线和文本批注；页面书签使用页级锚点，同一文档每页最多一个。每次创建或编辑均可明确选择是否保存当前译文快照。覆盖层使用归一化坐标，因此缩放和重新渲染不改变锚点；重开时会重新验证原文指纹。只有同页原文唯一匹配时才自动迁移，多义、缺失或文档哈希变化会保留记录并明确标记失效。批注面板支持类型/失效筛选、定位、编辑和删除；单篇文档最多 10000 条标记。

退出门禁：缩放、重开文档和切换显示模式后锚点仍正确；文档版本变化得到明确处理。

## 阶段 6：AI 阅读辅助

实现选区解释、章节总结、全文分块总结、当前论文检索问答、连续追问、英文引用、页码跳转和证据不足响应。

当前进度：SQLite 已迁移到版本 7，新增按文档哈希、任务类型、输入哈希、服务商、模型、Prompt 版本和用户指令版本隔离的 AI 助读缓存。右侧“AI 助读”支持选区解释、翻译并解释、当前章节结构化总结和需二次确认的整篇论文分块—综合总结。当前文献问答逐页提取文本并立即释放 PDF 字符坐标对象，用 PDF 目录标注章节，在本地以 BM25 排名候选片段；中文追问只允许模型生成有限英文检索词，不允许模型选择页码。候选证据由本地分配 `E1…En`；无引用、引用不存在、事实句未附引用或模型自行声称页码时，答案会被本地拒绝。通过校验的证据卡显示 PDF 页码、英文原文和章节，可跳转回对应页。

退出门禁：引用可反查，不允许模型生成无法定位的伪页码作为证据。

## 阶段 7：稳定性与 GitHub 发布

执行耐久、异常、迁移、卸载和恢复测试；扫描工作树、Git 历史、日志、数据库和自包含构建产物；生成安装包、隐私说明、已知限制和发布说明。

当前进度：版本已冻结为 0.1.0。SQLite 在线快照覆盖活跃 WAL 中的已提交事务，自动备份每日最多一次并保留 5 份；完整数据备份包含数据库、受管理 PDF 和设置，但明确排除 Credential Manager 密钥。损坏备份在替换前拒绝，恢复前另建可校验回滚快照。Windows x64 自包含 ZIP、原子安装/升级脚本、默认保留数据的卸载脚本、显式数据/凭据清理选项、SHA-256 清单、文件物料清单和 SPDX SBOM 已形成。隐私、安全、支持、已知限制、安装卸载、备份恢复和发布说明均已补齐。

自动门禁包括 schema 7 迁移与异常矩阵、93 项测试、500 页 5 标签短基准、1 分钟 974 轮加速耐久、隔离的全新安装/升级/完整数据恢复/两种卸载、自包含启动及最终产物扫描。GitHub remote 和外部发布不在自动流程中；人工验收后另行授权。8 小时交互桌面耐久属于发布前人工门禁，当前不声明已执行。

退出门禁：本地 Release 候选和首次 Git 提交通过扫描并可供人工验收；未配置明确 remote 时不得推送或创建 GitHub Release。

## 每阶段通用完成条件

- 核心代码有单元测试；资源生命周期和持久化路径有集成测试；
- 新功能具有取消、错误和空数据状态；
- 没有新增明文 Secret 路径；
- 文档和数据库迁移同步更新；
- Debug 与 Release 构建通过；
- 相关性能基准没有显著回退。
