# 阶段 0 性能基线

日期：2026-08-10  
状态：初步基线，不代表 V1 长文档验收结果

## PDFium 资源循环

输入为项目自有的两页固定样本。每轮执行：

1. 初始化并打开文档；
2. 提取一页 Unicode 文本和字符坐标；
3. 以 1.35 倍比例渲染一页 BGRA32；
4. 关闭文本页、页面和文档；
5. 最后一个文档关闭后销毁 PDFium 全局库。

命令：

```powershell
dotnet run --project .\tools\PaperBridge.PdfProbe\PaperBridge.PdfProbe.csproj --configuration Release -- .\output\pdf\pdfium-text-layer-sample.pdf 500
```

本机 500 轮结果：

- 用时：4.793 秒；
- 句柄：284 → 284，净增长 0；
- 私有内存：9,203,712 → 11,010,048 字节，净增长约 1.72 MiB；
- 工作集：30,945,280 → 33,681,408 字节，净增长约 2.61 MiB；
- 中间采样存在正常波动，最后回落，没有随轮次持续线性增长。

## 当前结论

固定小样本上没有发现文档、页面、文本页或位图句柄泄漏，资源曲线满足进入真实语料验证的条件。

该结果不能代替长 PDF、多标签和 8 小时耐久测试。进入阶段 1 前仍需加入真实的单栏、双栏、公式密集、图表密集及约 500 页样本，并在目标机器上冻结绝对缓存和内存预算。

## 多文档并发回归

阶段 1 的多标签实现加入了多文档集成测试：每轮同时持有 5 个 PDFium 文档实例，在工作线程上请求文本提取和页面渲染，完成后统一关闭，连续执行 10 轮。

测试最初暴露了 PDFium 跨文档并发调用导致的原生访问冲突（`0xC0000005`）。当前实现已将所有 PDFium 原生入口放入进程级同步区；多标签会话仍可独立取消和管理资源，但原生调用串行执行。修复后完整测试通过，未再出现测试宿主崩溃。

## 阶段 1：合成长文档与多标签基准

输入为项目生成的 500 页可选文本 PDF，页面循环覆盖单栏、双栏和表格版式。基准先完成 4 轮预热，然后执行 12 轮：每轮同时打开 5 个文档实例，每个实例分散抽取并渲染 3 页，最后关闭全部实例、强制完整回收并记录进程资源。

命令：

```powershell
python -m pip install -r .\tests\TestData\requirements-fixtures.txt
python .\tests\TestData\create_long_pdf_fixture.py
dotnet run --project .\tools\PaperBridge.PdfProbe\PaperBridge.PdfProbe.csproj --configuration Release -- --acceptance .\output\pdf\paperbridge-500-page-benchmark.pdf 12 5
```

本机结果：

- 样本：500 页，623,824 字节，SHA-256 为 `b335c949e73ca641d6dc8c42c5d34bc4dc03d3ddc92cb67c51f6ceaffe7b819f`；
- 冷打开、首页文本提取及 0.75 倍渲染：32 ms；
- 12 轮总用时：849 ms；
- 私有内存：16,027,648 → 18,112,512 字节，净增长 2,084,864 字节；
- 工作集：38,342,656 → 42,070,016 字节，净增长 3,727,360 字节；
- 句柄：330 → 330，净增长 0；
- 后 5 轮不存在持续性私有内存增长；自动判定通过。

原始 JSON 保存在本地构建产物 `artifacts/benchmarks/stage1-long-multitab.json`。

## 阶段 1 验收结论

合成 500 页长文档和多标签打开—读取—渲染—关闭循环已经通过，固定缓存预算和 PDFium 资源释放路径没有显示持续增长。

阶段 1 尚不能标记为完整通过：真实单栏、双栏、公式密集、图表密集、旋转页面及异常文本层语料仍未提供，8 小时交互耐久测试也尚未执行。当前结果允许继续开发阶段 2，但发布 V1 前必须补齐这些门禁。语料缺口见 `docs/BENCHMARK_CORPUS.md`。

## 阶段 7：发布候选资源回归

2026-08-11 在同一自生成 500 页样本上重新执行 12 轮、5 标签验收：冷打开/提取/首页渲染 402 ms，测试段 831 ms；句柄 330 → 330，私有内存净增长 1,781,760 字节，后 5 轮无持续增长，自动判定通过。

随后执行 1 分钟加速耐久：

```powershell
dotnet run --project .\tools\PaperBridge.PdfProbe\PaperBridge.PdfProbe.csproj --configuration Release -- --duration .\output\pdf\paperbridge-500-page-benchmark.pdf 1 5
```

- 实际 60.054 秒，974 轮，每轮 5 个文档、每文档抽取并渲染 3 页；
- 私有内存：19,095,552 → 25,374,720 字节，净增长 6,279,168 字节，采样多次回落且末段无持续增长；
- 工作集净增长 7,073,792 字节；
- 句柄：335 → 338，净增长 3；采样受线程池伸缩影响在有限范围内波动，末段无持续增长；
- 长测门禁允许最多 32 个一次性运行时句柄，同时要求末段不得持续增长；短基准仍使用净增长不超过 2 的严格门禁；
- 自动判定通过。

该加速测试覆盖高频打开、提取、渲染和关闭，不等同于真实用户交互、网络请求或 8 小时墙钟耐久。0.1.0 将 8 小时交互测试保留为 GitHub 发布前人工门禁，不作虚假完成声明。
